# Security Policy

## Supported scope

This repository contains infrastructure definitions and Kubernetes configuration. It is a home-lab reference implementation, not a maintained hosted service.

## Reporting a vulnerability

Do not publish credentials or exploit details in a public issue. Before making this repository public, maintainers must enable GitHub private vulnerability reporting in the repository's **Settings → Security → Code security and analysis**. Once enabled, use the repository's **Security → Advisories → Report a vulnerability** page to send a private report.

Private reporting is not yet confirmed as enabled. If it is unavailable, maintainers must publish a verified private contact method here before accepting vulnerability reports.

When reporting, include:

- Affected file and component
- Reproduction conditions
- Impact and attack prerequisites
- Suggested remediation
- Whether the finding is evidence-based or a design concern

Mask hostnames, addresses, usernames, and secret values in public reports.
